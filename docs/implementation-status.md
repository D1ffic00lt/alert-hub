# Implementation status

This page distinguishes code that exists in this repository from the complete distributed MVP
acceptance described by the product specification. Automated or controlled Docker evidence does
not prove the operator's real network, providers, runners, proxy, or iPhone.

The latest local backend verification completed 254 tests at 83.10% branch coverage, above the 75%
CI gate. Frontend lint/types, 23 unit tests, the production build, eleven Playwright paths, the
two-image Docker matrix, and the controlled three-node gate also passed locally. These results
become durable evidence for a reviewed commit only after its GitHub checks are green.

## Required before distributed MVP acceptance

| Area                   | Remaining evidence or capability                                                                                                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Real Web Push          | Exercise installation and user-gesture permission on a real iPhone Home Screen PWA; receive firing and resolved pushes while closed; verify deep-link click and reserve-node delivery after owner loss.                                                       |
| Real providers         | Test configured Web Push, Telegram, SMTP, and webhook accounts/endpoints from the intended egress network, including credentials, rate limits, provider responses, and ownership failover. Mocks do not prove external delivery.                              |
| Production topology    | Inventory and validate actual peer DNS/TLS, direct source-address preservation, exact `/32` proxy/application allowlists, firewall and public exposure, clock state, Prometheus labels/auth, Grafana links, and existing Nginx/Caddy configuration.           |
| Failure exercises      | Attach evidence for real one/two-node loss, RU↔EU partition/recovery, delivery-owner loss, runner offline, failed migration/readiness with automatic rollback, invalid proxy candidate restoration, manual `previous` rollback, and scheduled backup restore. |
| Replication lifecycle  | Design compact authenticated snapshot/bootstrap and tombstone/history retention, plus an authenticated operator workflow for resolving a detected bootstrap split brain. Empty-cursor full-history replay works but is not compaction.                        |
| Secret lifecycle       | Add and exercise bulk master-key re-encryption/rotation and an encrypted offline key-recovery procedure. Database backup alone cannot recover encrypted provider/subscription values.                                                                         |
| Browser hardening      | Add installation-level CSP reporting and replace the remaining narrowly scoped inline-style allowance with a nonce/hash or equivalent design after validating the production proxy/runtime integration.                                                       |
| Release infrastructure | Configure branch protection, protected tags/environments, repository-scoped self-hosted runners and root-owned wrappers on the real nodes; then exercise a protected release and ordered deployment.                                                          |

The detailed register is in [acceptance evidence](acceptance-evidence.md). Do not describe a
release as the distributed MVP until every applicable external row has dated evidence and the
real-iPhone Web Push flow has passed.

Database migrations remain forward-only and compatible with application version N-1. Ordinary
application rollback never downgrades or restores SQLite; database restore is a separately
confirmed disaster-recovery operation.
